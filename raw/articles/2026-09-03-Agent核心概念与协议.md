## 内容摘要

文章从 LLM 的能力边界出发，梳理 Agent、Workflow、Function Call、MCP、Skills 和 A2A 的分工。它的主线是：LLM 提供推理和生成，Agent 通过工具、记忆、规划与循环把能力延伸到外部世界；Workflow 由代码控制流程，Agent 由模型根据当前状态决定下一步。

## 关键内容

- LLM 被概括为强大的文本生成与推理引擎，但本身不直接执行外部操作、不天然持久记忆，也不负责长期任务规划。
- Agent 的常见工作模式包括 ReAct（边想边做）、Plan-and-Execute（先计划后执行）、Reflection（执行后检查）和 Multi-Agent（多个角色协作）。
- Function Call 是模型按结构化参数请求外部函数的基础能力；MCP 被文章定位为统一 Agent 与工具/资源连接的协议层；Skills 是承载“怎么做”的知识与流程层。
- A2A 面向 Agent 之间的发现、通信和协作，与 MCP 构成“Agent 连接工具”和“Agent 连接 Agent”的互补关系。协议角色、消息格式和生态状态需要以官方规范为准。
- 文章用“谁控制流程”作为 Agent 与 Workflow 的判断标准，但实际系统可以把确定性的 Workflow 节点和模型决策节点混合使用。

## 与专栏其他文章的关系

这是专栏的概念地图。[[OpenClaw 本地自主 Agent]] 是这些概念的本地执行案例；[[Graph Engineering]] 把“流程由谁控制”进一步落实为节点、边和状态；[[Claude Code 工程化六件套]] 则把 Skills、Subagents、MCP 和 Hooks 放进具体工程协作边界。

## 待核实

- MCP、A2A 的版本、官方定义与生态现状需要分别回查协议原文。
- ReAct、Reflection 等模式的优劣是文章的工程化归纳，不应直接视为统一 benchmark 结论。
