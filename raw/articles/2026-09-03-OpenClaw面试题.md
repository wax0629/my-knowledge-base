## 内容摘要

文章把 OpenClaw 解释为可以长期运行在个人设备上的自主 AI Agent：它在大模型之上补足本地执行、消息接入、设备感知和长期记忆，使 Agent 从“回答问题”变成“持续替用户做事”。全文以面试题形式介绍架构、记忆、适用边界和成本。

## 关键内容

- 架构角色包括 Gateway、Agent、Tools、Skills、Channels 和 Nodes。Gateway 负责鉴权、会话管理与路由；Agent 负责拆解和推进任务；Tools 是单项能力，Skills 是组合流程；Channels 适配飞书、微信、Telegram 等消息入口；Nodes 把手机或电脑上的摄像头、位置、屏幕和系统控制等能力接入 Agent。
- 文章强调本地常驻、跨平台通信、主动执行和可扩展技能是其与普通聊天机器人或一次性 Agent 的差异。
- 记忆被描述为“短期日志 + 长期 Markdown + 轻量索引”的混合方案：近期会话保存在按天日志中，重要事实提炼到 `MEMORY.md`，再用 SQLite 向量检索和 BM25 组合召回。该实现描述需要回到目标版本源码核验。
- 文章从执行权限、隐私泄露、误操作、后台自主试错和模型成本等角度讨论缺点，并比较 OpenClaw、Coze 与 n8n：前者偏本地自主执行，后两者更偏云端搭建或流程编排。具体产品边界随版本变化。
- Token 消耗来自持续轮询/心跳、多轮工具试错、长期记忆抽取与召回，以及每次请求都要携带的工作空间规则和工具清单。
