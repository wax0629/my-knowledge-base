## 内容摘要

文章把 Grok Bot 描述为运行在专属云端计算机上的常驻型 Agent：它可以登录用户已有的网站和应用，直接操作界面，持续推进任务，并通过多个 Bot 的分工、通信和工作流录制完成较长的自动化流程。文章同时强调，越接近“无需等待用户下一条指令”的系统，越需要明确审批、权限和止损边界。

## 关键内容

### 云端常驻与界面操作

- 每个 Bot 据文章描述拥有一台持续运行的小型云计算机，因此可以在用户电脑关闭时继续执行定时任务。
- Bot 可以登录用户正在使用的网站和应用，观察用户完成工作流的过程，并把步骤固化为可重复调用的操作模板。
- 文章强调它可以打开浏览器、登录网站、填写表单和点击按钮，因此没有 API 或 MCP 的传统软件也可能通过界面层被操作。

### 多 Bot 协作

- 用户可以创建销售、招聘、费用、Bug 复现等不同角色的 Bot，让它们并行工作。
- Bot 之间可以直接发送消息、汇报进度、分配任务，并被放入群聊自主协商分工。
- 文章进一步声称 Bot 可以创建新的 Bot，形成带名字、头像、职位和分组的 Bot 团队。
- 文章把这种管理 Bot—Worker Bot 的结构与 [[Graph Engineering]] 中的协调、分支和汇合相联系，也把会话间通信与 [[Claude Code 多智能体协作]] 做了跨产品对照。

### 工作流录制与演化

- 文章描述了一种类似 Record & Replay 的能力：用户先演示任务，Bot 记录步骤，之后按计划或由 Slack/GitHub 等事件触发。
- 执行中用户可以纠正 Bot，修正会被纳入后续例程。文章用“带新人做一遍”的比喻说明这种学习方式。
- 文章还提到夜间运行、通过模拟器玩 Wii 棒球等用户体验案例，但这些案例需要原始演示或独立证据支持。

### 价格与可用范围

- 文章声称 Grok Bot 面向 SuperGrok Heavy（每月 300 美元）、Cursor Ultra（每月 200 美元）和 Cursor Teams Premium（每席位每月 120 美元）用户开放。
- 文章称桌面端与 iOS 可用、Android 尚未上线，企业用户需要申请候补名单。
- 文章还将 Grok Bot 的原型、Cursor 基础设施及 xAI/Cursor 的公司关系串联起来；这些并购、改名和产品归属信息不能仅凭公众号转述确认。

### 风险与取舍

- 云端常驻提高了后台自动化和多任务并行能力，也提高了登录凭证、网页操作、误提交和错误扩散的风险。
- “不用等你”如果没有审批门禁，可能变成“不必问你”：一个早期小偏差可能沿着多个自动化步骤放大。
- 文章指出该系统目前绑定 Grok 模型，工作流迁移到其他模型的路径有限；这会形成模型质量和供应商生态锁定。

## 与已有知识的关系

[[OpenClaw 本地自主 Agent]] 提供本地优先、消息通道、设备节点和长期记忆的对照案例；[[Claude Code 多智能体协作]] 提供上下文隔离、协调者和异步通信的 coding agent 案例；[[Harness Engineering]] 和 [[Loop Engineering]] 分别对应权限/验证/恢复与持续运行；[[Graph Engineering]] 对应多 Bot 的任务依赖和汇合。

## 我的理解

Grok Bot 文章真正值得保存的不是单一产品价格，而是“常驻执行环境 + 界面层工具 + 可复用工作流 + 多 Agent 协作”这一组合。评估此类系统时，必须同时测任务完成率、权限范围、审批触发、可回滚性、凭证隔离、错误传播和模型替换成本；只看它能否完成演示任务是不够的。
