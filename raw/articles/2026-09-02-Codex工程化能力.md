## 内容摘要

文章以作者从 Claude 转向 Codex 的经历为引子，介绍 Codex 中五类工程化能力：`AGENTS.md`、Skills、Subagents、MCP 和 Hooks。文章的核心观点是，把项目规则、按需加载的专项流程、并行子任务、外部系统连接和生命周期自动检查分别放在合适的机制中，可以让 Agent 更稳定地参与真实项目工作。

## 主要内容

### 1. AGENTS.md：项目规则和上下文

文章把 `AGENTS.md` 比作项目的入职手册，用来记录目录约定、正文格式、修改边界和检查命令。示例规则包括：正文使用中文、一篇文档只保留一个一级标题、图片放入 `images/`、`published/` 目录只读，以及修改后运行检查脚本。

文章还介绍了规则的层级加载：个人规则放在 `~/.codex/AGENTS.md`，项目根目录放团队规则，子目录可放模块专属规则；同一层同时存在 `AGENTS.override.md` 和 `AGENTS.md` 时优先选择 override 文件。规则从根目录向当前目录合并，越靠近当前目录的规则优先级越高。文章称合并后的默认总大小上限为 32 KiB。

### 2. Skills：按需加载的专项流程

Skills 用于封装并非每个任务都需要的专项知识和操作流程，例如根据 Git Tag 生成可追溯的 Release Notes 草稿。文章强调 Skill 的渐进式加载：平时只读取名称和描述，任务匹配后再读取 `SKILL.md`，必要时继续读取 `references/`、`scripts/` 和模板。

文章给出的项目级目录示例是 `.agents/skills/`，个人跨项目目录示例是 `~/.agents/skills/`。一个最小 Skill 由 `SKILL.md` 构成，描述何时使用、执行步骤、输入输出和禁止的副作用。

### 3. Subagents：拆分独立上下文并行工作

Subagent 被描述为由主任务临时派出的独立线程，适合将产品能力、接入方式、迁移风险等互相独立的调查并行展开。主 Agent 负责任务分工、等待结果、去重和合并结论，子任务中的搜索结果和中间过程不必全部占用主上下文。

文章区分了临时 Subagent 和可重复使用的自定义 Agent：前者可直接在提示词中派发，后者通过岗位模板固定职责。文章示例把自定义 Agent 配置放在 `.codex/agents/`，并提到 `default`、`worker`、`explorer` 等通用 Agent。

文章还指出，Subagent 默认继承主任务权限；Subagent 解决上下文和分工隔离，Worktree 解决文件层面的隔离。多个任务同时修改同一批文件时可能发生冲突。

### 4. MCP：连接仓库外的系统

MCP（Model Context Protocol）被文章比作 AI 工具的通用插座，用统一的工具说明和通信规则连接 Google Drive、GitHub、数据库或其他外部系统。文章使用 Google Drive 作为例子，描述查找文档、读取内容并整理结果的流程。

文章用 Host、MCP Client 和 MCP Server 解释角色分工：Host 负责理解任务和选择工具，Client 负责通信，Server 负责实际执行。MCP Server 除了提供可执行的 Tools，还可以提供可读取的 Resources 和可复用的 Prompts。

### 5. Hooks：绑定任务生命周期的自动检查

Hooks 被描述为在 Codex 任务生命周期节点自动调用 Handler 的触发器，适合测试、格式化、安全扫描、上下文加载和结果记录等固定动作。文章列举了 `SessionStart`、`UserPromptSubmit`、`PreToolUse`、`PostToolUse` 和 `Stop` 五类节点。

文章给出的 Stop Hook 例子是在任务准备结束时运行 `python3 scripts/check_docs.py`：检查通过则结束任务，检查失败则把摘要交回 Codex 继续处理。文章称 Codex 会通过标准输入向 Handler 传递工作目录、事件名称以及工具名称和参数等信息，再通过退出码或 JSON 结果决定继续、停止或补充上下文。

## 文章中的归纳

文章最后用一张表概括五项能力的分工：

- `AGENTS.md`：让 Codex 在项目中持续遵守固定规则。
- Skills：封装可复用的专项知识和操作流程，按需加载。
- Subagents：拆分独立子任务，并行调查并汇总结果。
- MCP：连接仓库外的数据、工具和系统。
- Hooks：在固定生命周期节点自动执行动作。

这五项能力覆盖了“规则、知识、分工、连接、自动化”五个不同层面，不应把它们都堆进项目规则文件或每次任务的提示词中。
