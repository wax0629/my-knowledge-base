# RAG 检索与评估

## 摘要

RAG（Retrieval-Augmented Generation）通过先检索外部知识、再把相关内容交给模型生成答案，缓解知识过期、私有数据不可见和部分幻觉问题。一个可用的 RAG 不是“接一个向量库”这么简单，而是包含切分、索引、召回、精排、上下文构造、生成和持续评估的完整系统。

## 核心内容

### 基本链路

1. 文档切分：按固定大小、递归字符、文档结构、语义或 Agent 策略拆成片段。
2. 表示与索引：用 Embedding 将片段转换为向量，并保存到向量索引/数据库，同时保留元数据和原文位置。
3. 查询与召回：把问题转换为查询，使用向量、关键词、BM25、元数据或领域检索器获取候选。
4. 精排与组装：用 Re-rank 对候选相关性重新排序，控制上下文长度，加入来源和边界。
5. 生成与验证：让模型基于检索内容作答，再检查忠实度、相关性和风险。

### 关键设计选择

- 切分要尽量保持语义单元完整，并根据查询粒度、文档结构和上下文预算调整。
- Re-rank 适合在较小候选集上做更精细的查询—文档联合判断；不应把所有候选都交给高成本模型。
- 多路召回通过组合语义相似和精确关键词，降低单一路径漏召回或误召回的风险。
- 向量数据库选型应同时看过滤、更新、规模、部署、成本、可观测性和运维，不要只看单次检索速度。

### 评估与幻觉控制

检索评估关注召回的相关性、覆盖和排序；生成评估关注 Faithfulness、Answer Relevance、Context Relevance 等。文章介绍 RAGAS、DeepEval、TruLens 和 ARES，并建议先建基线、使用代表性问题集、持续监控并接入 CI/CD。降低幻觉还可以配合 Prompt 约束、独立校验、领域微调、不确定性量化和图检索。

## 我的理解

RAG 的工程难点在“检索到什么、以什么顺序、以什么证据形式交给模型”，而不是单独追求更大的 Embedding 模型。应把召回、精排、生成和事实核验拆成可观测阶段，用失败样本判断是知识缺失、切分错误、召回错误还是模型过度推断。
