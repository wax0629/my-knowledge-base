# Claude Code 代码检索策略

## 摘要

代码检索与自然语言文档检索的目标不同：代码经常要求精确符号、当前版本、完整结构和调用关系。专栏文章把 Claude Code 的路线概括为 Agentic Search，即让模型在当前工作树上通过 `Glob`、`Grep`、`Read` 和必要的 LSP/子 Agent 逐步寻找证据，而不是默认依赖预先建立的向量索引。

## 核心内容

### 代码场景对 RAG 的挑战

- 固定切块可能切断函数、条件分支或调用关系。
- 向量检索擅长相似匹配，但用户经常要找一个精确函数名、路径或配置键。
- 代码持续提交、重命名和移动，预建索引可能过期。
- 大型仓库建立索引有冷启动和维护成本，检索结果还不一定可解释。

### Agentic Search 三件套

- `Glob`：用路径或文件名模式缩小候选范围。
- `Grep`：按符号、关键词或内容搜索，并保留位置线索。
- `Read`：只读取当前需要的文件和上下文，避免一开始贪心加载整个仓库。

模型先从目录/入口开始，读取候选结果后决定下一轮搜索；复杂任务可以让只读子 Agent 做探索，再由主 Agent 合成。LSP 可进一步提供符号定义、引用和跳转信息，弥补纯文本搜索的边界。

### 适用边界

实时搜索适合频繁变化、结构化、需要精确定位的代码库；RAG 仍适合静态自然语言文档、跨库语义问答和难以用关键词表达的概念检索。两者可以组合，例如用符号/关键词确定范围，再用语义检索补充相关背景。

## 我的理解

代码检索的关键不是“语义相似度最高”，而是尽快找到可验证的当前证据。一个好的 Agent 搜索过程应留下起点、搜索词、候选路径、读取范围和最终依据，让人可以复盘它为什么选择某个文件。对于高风险修改，检索结果必须再由测试、编译或人工 Review 验证。
