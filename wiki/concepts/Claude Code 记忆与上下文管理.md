# Claude Code 记忆与上下文管理

## 摘要

专栏文章把 Claude Code 的长期记忆和上下文压缩看成两套互补机制：静态 `CLAUDE.md` 提供稳定规则，动态记忆文件保存交互中抽取的用户/项目事实；上下文管理则从工具结果落盘、旧消息裁剪到全量摘要逐级减负。共同目标是让模型只看到当前任务需要的、可验证的信息。

## 核心内容

### 两层记忆

静态层是分级加载的 `CLAUDE.md`，适合项目约定、命令、安全边界和稳定偏好。动态层是运行中抽取的记忆文件，文章将其分为 `user`、`feedback`、`project`、`reference` 四类，并用索引记录路径、摘要和来源，正文在需要时才读取。

文章描述的动态记忆闭环是：一轮主循环结束后由独立代理抽取新事实，与已有记忆去重并分类写入；下一次会话先让选择器根据文件头部信息选少量候选，再用系统标记注入正文。旧记忆应附带老化提醒，文件路径、函数名和配置项在使用前重新验证。

### 五层上下文压缩

1. 大工具结果落盘，只在上下文保留预览。
2. Snip 删除已经失去价值的早期探索消息。
3. Micro-Compact 清理可重复获取的旧工具结果，保留最近或不可重复的状态。
4. Context Collapse 在读时生成压缩投影，不改动本地原始消息。
5. Auto-Compact 在前四层仍不足时重写历史摘要，并重新注入文件、记忆和异步任务状态。

这套顺序体现“先用本地、轻量、可恢复的办法，再使用 API 成本更高的全量摘要”。摘要应保留目标、当前进度、关键决策、错误和下一步，而不是机械复制全部对话。

## 我的理解

“记忆”不等于把更多历史塞进 Prompt。可用记忆至少需要 schema、索引、选择、时效和验证；上下文压缩也不应只追求更高压缩率，而要明确哪些状态可以重新读取、哪些结果不可重建。把状态放到文件或结构化对象后，还必须为并发写入、过期和错误恢复设计约束。
