# 文件型知识库工作流

## 摘要

文件型知识库以普通 Markdown 文件夹作为唯一真源，把原始材料、整理结果和问答产出分开保存，再由 Agent 按规则维护。它的优点是结构透明、迁移成本低、可以接入不同编辑器和 AI 工具。

## 核心内容

- `raw/` 保存原始资料，原则上只新增、不改写。
- `wiki/` 保存可长期复用的主题知识。
- `outputs/` 保存报告、摘要、提纲和草稿。
- `INDEX.md` 提供导航，`AGENTS.md` 提供维护规则。
- Agent 的主要职责是增量整理、建立主题关系、保留来源和发现冲突。
- 原始资料和整理结果分离，便于重新编译和追溯。

## 与已有知识的关系

本知识库的目录和入库流程直接采用这一模式，并增加了 `assets/` 附件目录、Git 版本管理和 Codex 工作区。

## 我的理解

知识库的核心不是 Obsidian 或某个 Agent，而是稳定的文件格式和清晰的维护规则。编辑器和 Agent 都可以替换，文件不应被锁定在单一产品中。
